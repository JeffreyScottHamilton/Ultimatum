# Token templates: plain CSS variables and a Tailwind v4 theme

Read when wiring tokens into a real stylesheet: a plain-CSS site, or a Tailwind CSS v4 project (with or without shadcn/ui). Both templates below are generated by `tools/build_tokens.py` from `../../../../../data/design-own/tokens/starter.tokens.json`; the full files are `starter.tokens.css` and `starter.theme.css` in the same folder. The layer model behind them is in `token-architecture.md`.

## Template 1: plain CSS custom properties

For any site without Tailwind. Four blocks, in this order:

```css
/* 1. Primitives */
:root {
  --color-ink-50: #f6f7f6;
  --color-ink-950: #101312;
  --color-moss-400: #6aa886;
  --color-moss-600: #2f6b4f;
  --color-white: #ffffff;
  --spacing: 0.25rem;
  --radius: 0.5rem;
  /* ...the rest of the ramps, type, motion, shadow */
}

/* 2. Semantic roles, light */
:root {
  --background: var(--color-ink-50);
  --foreground: var(--color-ink-900);
  --primary: var(--color-moss-600);
  --primary-foreground: var(--color-white);
  /* ... */
}

/* 2. Semantic roles, dark: only roles change */
.dark {
  --background: var(--color-ink-950);
  --foreground: var(--color-ink-100);
  --primary: var(--color-moss-400);
  --primary-foreground: var(--color-ink-950);
}

/* 3. Component tokens */
:root {
  --button-bg: var(--primary);
  --button-fg: var(--primary-foreground);
  --button-height: 2.75rem;
  --button-radius: calc(var(--radius) - 2px);
}
```

Use it:

```css
body   { background: var(--background); color: var(--foreground); }
.button {
  color: var(--button-fg); background: var(--button-bg);
  min-height: var(--button-height); border-radius: var(--button-radius);
  padding-inline: calc(var(--spacing) * 4);
}
```

To follow the OS setting as well as a manual switch, add the same dark block inside `@media (prefers-color-scheme: dark) { :root:not(.light) { ... } }`, and let the switch set `.dark` or `.light` on `<html>`. Set `color-scheme: light dark` on `:root` so form controls and scrollbars match. Details: `../hallmark/dark-mode.md` § Emission.

## Template 2: Tailwind CSS v4 theme

Tailwind v4 is configured in CSS. Variables in an `@theme` block become both CSS variables and utility classes, by namespace: `--color-*` makes `bg-*`, `text-*`, `border-*`; `--font-*` makes `font-*`; `--text-*` makes text sizes; `--spacing` drives every spacing utility; `--radius-*` makes `rounded-*`; `--shadow-*`, `--ease-*`, `--breakpoint-*` likewise (https://tailwindcss.com/docs/theme).

```css
@import "tailwindcss";

/* Dark mode by class on <html>, instead of the default OS media query */
@custom-variant dark (&:where(.dark, .dark *));

/* 1. Primitives: also become utilities (bg-moss-600, text-ink-900) */
@theme {
  --color-*: initial;              /* drop Tailwind's default palette; only ours exists */
  --color-ink-50: #f6f7f6;
  --color-moss-600: #2f6b4f;
  --color-white: #ffffff;
  --font-sans: "Public Sans", system-ui, "Segoe UI", Roboto, sans-serif;
  --text-base: 1rem;
  --spacing: 0.25rem;
  --radius: 0.5rem;
  --shadow-sm: 0 1px 2px rgb(16 19 18 / 0.08);
  /* ... */
}

/* 2. Semantic roles: plain variables, switched by .dark */
:root { --background: var(--color-ink-50);  --primary: var(--color-moss-600); /* ... */ }
.dark { --background: var(--color-ink-950); --primary: var(--color-moss-400); /* ... */ }

/* 2b. Expose roles as utilities: bg-background, text-primary-foreground */
@theme inline {
  --color-background: var(--background);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --radius-md: calc(var(--radius) - 2px);
  --radius-lg: var(--radius);
  /* ... */
}
```

Why each piece is there:

- `--color-*: initial` clears the default colour namespace, so nobody reaches for a stock palette colour outside the system. Leave it out if the project wants the defaults too.
- Semantic roles live in `:root`/`.dark`, not `@theme`, because they must change at runtime. `@theme inline` is the documented way to register a theme variable whose value is another variable: the utility then uses the variable's live value, so `.dark` switches every `bg-primary` without new classes (https://tailwindcss.com/docs/theme).
- `@custom-variant dark` makes `dark:` utilities follow the `.dark` class; without it they follow `prefers-color-scheme` only (https://tailwindcss.com/docs/dark-mode). For a data attribute instead, use `@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));`.
- Radius steps derive from one `--radius`; shadcn/ui's theme does the same (`shadcn-theming.md`).
- Fonts are only named here. Load them by link or self-host with their licence (`../hallmark/fonts.md`).

Use it:

```html
<body class="bg-background text-foreground font-sans">
  <article class="bg-card text-card-foreground border border-border rounded-lg p-6 shadow-sm">
    <p class="text-muted-foreground text-sm">Updated today</p>
    <button class="text-primary-foreground bg-primary hover:bg-primary-hover rounded-md h-11 px-4">Save</button>
  </article>
</body>
```

## How both templates were checked

Run in this session, in a scratch folder outside the repo:

| Step | Command | Result |
|---|---|---|
| build | `python3 tools/build_tokens.py` | exit 0; 28 pair checks (14 pairs x 2 modes) all at or above floor |
| stale check | `python3 tools/build_tokens.py --check` | exit 0, "tokens: up to date" |
| compile | `npx tailwindcss -i starter.theme.css -o out.css` with tailwindcss 4.3.5 | exit 0; `.bg-primary` compiled to `background-color: var(--primary)` |
| render | Playwright Chromium, both pages, `.dark` toggled on `<html>` | computed values below |

| Element | Light | Dark |
|---|---|---|
| body background / text | rgb(246, 247, 246) / rgb(28, 32, 31) | rgb(16, 19, 18) / rgb(236, 238, 237) |
| button background / text | rgb(47, 107, 79) / rgb(255, 255, 255) | rgb(106, 168, 134) / rgb(16, 19, 18) |
| muted text (Tailwind page) | rgb(83, 92, 88) | rgb(185, 192, 189) |
| button height, radius | 44px, 6px | 44px, 6px |
| card radius (Tailwind page) | 8px | 8px |

Both the plain-CSS page and the Tailwind page gave the same button and body values, matching the hex values in the JSON. The first build also caught a real fail (dark muted text on the muted ground at 4.41:1); the fix was one step lighter in the JSON.

## Adapting the starter

1. Copy `starter.tokens.json` into the project (for example `design/tokens.json`).
2. Replace the `moss` and `ember` ramps with the brand's, keeping the step names; adjust the neutral ramp's warmth to suit.
3. Keep or extend `pairs`: add any pair the design actually uses (text on an accent panel, a link colour on a card).
4. Run the generator with `--out-dir` pointing into the project's styles; import `tokens.css` or `theme.css` (not both).
5. Add `--check` to CI.
