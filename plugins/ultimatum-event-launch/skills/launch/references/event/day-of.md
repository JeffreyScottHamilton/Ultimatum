# Day of: the run sheet

A run sheet is one page that says what happens when, who does it, and who steps in if they cannot. Draft it two weeks out, review it with the organiser and helpers in launch week, and share the final version the day before.

## Template

Fictional example for a three-hour in-person workshop starting at 10:00.

| Time | What | Owner | Backup | Notes |
|---|---|---|---|---|
| 08:30 | Arrive, unlock, lights, heating | Ana (host) | Ben | Keys and alarm code held by the organiser, not in this file |
| 08:45 | Set up tables, materials, signage | Ben | Ana | Signage list below |
| 09:15 | Check-in desk ready, list loaded | Cara | Ben | Printed list as backup |
| 09:30 | Doors open, check-in | Cara | Ben | Photo-consent stickers |
| 10:00 | Welcome, safety notes, toilets, exits | Ana | Ben | |
| 10:10 | Session part 1 | Ana | | |
| 11:15 | Break | All | | Refreshments |
| 11:30 | Session part 2 | Ana | | |
| 12:45 | Wrap-up, next event, feedback link | Ana | Cara | QR code on a card |
| 13:00 | Close, goodbyes | All | | |
| 13:30 | Pack down, check the room | Ben | Cara | |

Add a contacts block at the top: names and roles only, with phone numbers shared privately among the team, not stored in Git or chat logs.

## Check-in

- An attendee list exported the day before; a printed copy as backup.
- Mark arrivals; note no-shows for the results review.
- Walk-ups: decide in advance whether you accept them and how they pay.
- Waitlist: if someone has not arrived by a set time, decide whether to offer their place.

## Signage

- Outside: event name and arrow, visible from the street.
- Route to the room, toilets, exits, step-free route.
- Wi-Fi details if offered; photo notice (below).

## Online events: tech check

- Rehearse with the host a day or two before: link, audio, camera, screen share, slides.
- Check the start time in the time zones of the audience.
- One person runs the tech, admits people, watches the chat; the host only hosts.
- Backup: a second device with the host's slides and a phone hotspot.
- Captions turned on if the tool supports them.

## Recording consent

- Say on the event page and at the start if the event is recorded, and where the recording will go.
- In person: let people sit out of camera view; use stickers or wristbands for "no photos".
- Online: announce recording before starting it; let people turn cameras off.
- Children or vulnerable people: get the right consent or do not record them; rules here are **check locally**.

## Accessibility

- Step-free access, seating, accessible toilet: confirm with the venue and describe them on the event page.
- Large-print handouts or slides shared in advance on request.
- Quiet space for breaks if the event is long or loud.
- For online events: captions, a dial-in option if possible, slides shared in advance.
- Ask registrants about access needs in the form and read the answers before the day.

## Who answers messages

Name one person who watches email, social messages and the sign-up tool from two hours before start until one hour after the end. They have the address, parking or link details, and a short list of approved answers. Nobody else replies, to avoid mixed answers.

## Photo and video capture

- A shot list: the space, the host in action, hands at work, people (with consent) enjoying it, a group photo at the end (opt-in).
- One person or one phone responsible; capture horizontal and vertical.
- Only people who agreed appear identifiably. Mark or skip the others.
- Media goes to the organiser's drive, not to Git.
- These photos feed the follow-up and the next event's promotion.

## Things to bring (adapt)

Printed run sheet and attendee list, signage and tape, chargers and extension lead, first aid kit (venue's or your own: check locally), name tags and pens, feedback cards with QR code, water, spare materials.

## Safety and permits

Fire exits, capacity, first aid, food handling, alcohol and insurance are the organiser's and the venue's responsibility. They are listed in `launch-checklist.md` as items to **check locally**.
