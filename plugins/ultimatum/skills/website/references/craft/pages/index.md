# Page anatomy: index

Read when building a page whose type has known jobs: a marketing landing, a landing for a developer product, or a settings area. One line per file. Written by Ultimatum; the topic list was checked against the MIT-licensed frontend-stack plugin's page references, none of its text is used. These say what each part of the page must do, not how it looks: the direction (`../hallmark/direction.md`) and the house rules (`../../website/design-rules.md`) decide the look and win on any conflict.

1. `landing.md`: the questions a marketing page answers and in what order, navigation, the action pair, devices that explain, and a first-screen test.
2. `devtool-landing.md`: what changes when the buyer is a developer or a coding agent: real code, a catalogue, billing units, the path to a first request.
3. `settings.md`: settings areas for web apps, desktop apps, CLIs and terminal UIs: scopes, structure, save behaviour, the row, danger actions, and a build order.
